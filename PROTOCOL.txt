====================================================
RFMP PROTOCOL - PACKET FORMATS (v1.0)
Matches the exact notation in the assignment document
====================================================

All packets: parentheses wrapping comma-separated fields.
Send each packet with a newline (\n) at the end so the other
side knows where it stops - read byte-by-byte until you hit \n.

1. Start-Packet (client -> server):
   (SS, RFMP, v1.0, 0)     - 0 = no encryption
   (SS, RFMP, v1.0, 1)     - 1 = encryption on, expect an
                              Encryption-Packet right after

2. Confirm-Connection-Packet (server -> client):
   Not secure: (CC)
   Secure:     (CC, Server_public_key)

3. Encryption-Packet (client -> server, only if secure = 1):
   (EC, Algorithm, session_key, username:Client_public_key)
   Algorithm = AES or Caesar
   session_key = the AES/Caesar key, encrypted using the server's
                 RSA public key before sending

4. Command Packet (client -> server):
   (CM, command_type, arguments)
   Examples:
     (CM, prompt, ls)
     (CM, prompt, mkdir folder1)
     (CM, prompt, ren homework1 homework2)
     (CM, openRead, data.txt)
     (CM, openWrite, data.txt)

5. Data Packet (either direction, after openRead/openWrite):
   (DP, text)
   - "text" is the file content, encrypted if secure = 1

6. Success Packet (server -> client):
   (SC, message)

7. Exception Packet (server -> client):
   (EE, ErrorCode, Description)
   - max 4 distinct error codes

8. Close Packet (client -> server):
   End
